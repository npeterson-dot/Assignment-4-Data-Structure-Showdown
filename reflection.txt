For the timed challenge, I chose to use a set because the main goal of the problem was to count how many unique words were in a list. A set made the most sense because it automatically removes duplicate values, which meant I did not have to manually compare every word in the list. After converting the list of words into a set, I could use len() to return the number of unique words. This kept the solution short and easy to understand.
The 30-minute time limit made me focus on finding the simplest structure that could solve the problem correctly. Instead of trying to create a more complicated solution, I thought about what I needed the data structure to accomplish. Since order did not matter and duplicates needed to be removed, a set seemed like the most direct choice. This also gave me more time to think about testing instead of spending most of the time writing the solution. 
One trade-off with using a set is that it does not preserve the original order of the words, but that was not important for this problem because I only needed to return a count. I also added a check for the wrong data type and tested the function with normal values, duplicate values, an empty list, and all unique values. Under the time limit, I focused on keeping the solution simple, readable, and able to handle the main edge cases.
